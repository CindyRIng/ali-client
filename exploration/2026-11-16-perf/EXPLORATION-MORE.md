# 「更全的河北企业」路径探索（2026-11-16，绕过 ali-client 直接开浏览器）

> 目标：在现有 1559 家（3541 候选）之外，寻找阿里国际站上**按省/市/县列出企业**的其它入口或隐藏过滤能力。
> 方法：使用服务 profile 副本单独启动 headless 浏览器，不经过 ali-client；直接观察页面、网络请求、内部 API。
> 结论先说：**没有找到可用的“官方全量目录/省级过滤”**；平台对中国的「省」过滤是空的，其余“地区页”本质是关键词 SEO 页。

## 1. 尝试过的路径与结果

| # | 路径 | 结果 |
|---|---|---|
| 1 | 搜索 URL 加 `&province=Hebei` / `provinceCode=130000` / `city=...` | **被忽略**：结果集与不加参数一致 |
| 2 | 搜索页筛选面板 `Province` | 存在该 group，但 **values 为空**；`Supplier country/region` 只有国家；对中国不提供省过滤 |
| 3 | `countrysearch/CN/{市/县}-suppliers.html` 地区页 | 126 个河北市/县 × 2 种拼音 slug，抓到 **3166 个唯一店铺子域**；但页面本质是「关键词: X suppliers」的搜索页，**不是地区目录**。随机抽 19 家详情：**0 家河北**；只有少数产业县（Anping/Qinghe）正好命中本地公司。 |
| 4 | 新版 `/search/page` SPA 的搜索 API | 发现 `/search/api/supplierTextSearch`、`wendingSearch`、`supplierAiMatch`；JSON 每页 20 家、最多约 20 页。页面会显示 “Province: Hebei” 标签，但 **API 不执行省过滤**（query=a/manufacturer 结果仍混有广东/河南/江西…；`supplierAttributes=Province: Hebei` 也无效；province/city 参数也无效；>20 页返回空） |
| 5 | 公司详情页「相似/推荐供应商」 | 静态 HTML 内只有自身子域；推荐未发现可用列表（懒加载/无相关接口） |
| 6 | 手机站 / sitemap / robots | 手机搜索 `Failed to fetch`；sitemap 不可用；robots 无可用的企业索引 |
| 7 | 阿里「认证工厂」目录（insights gateway） | 有 province 字段，但总量约 500，河北仅 4 家 |
| 8 | 中文关键词 / 拼音变体（524 个 ID 抽样） | **0 个新公司**（相对现有档案 4362 家）→ 关键词路径已接近饱和 |
| 9 | 行业词 + 省 strict（wire mesh / bearing / glass） | wire mesh 命中 30 家全部已知；bearing 2 家已知；glass 0 → 在 maxEnrich 60 下边际收益很低 |
| 10 | `sale.alibaba.com/p/factories/...rank_list` | 品类榜单/工厂榜，非地区目录 |

## 2. 关键证据

- 搜索筛选数据里 `{"title":{"name":"Province"},"type":"Supplier Features","values":[]}` —— 省过滤是空数组，说明平台对中国不提供省选项。
- 新版搜索 API 的 `paginationData: {currentPage, totalPage: 50, totalCount: 0}`，但实际 `page>20` 返回空，说明有约 20 页的硬上限（≈400 家/关键词）。
- 地区页抓到的 3166 个子域里：
  - 与现有档案重叠 582（其中已知河北 133）
  - **新子域 2584**，但随机样本河北率 0/19 → 必须逐家详情验证才有意义。
- 行业词 strict 依赖 `maxEnrich=60`，只能验证搜索结果前 60 家；关键词搜索本身又混入大量外省贸易商，所以「逐家详情确认」成本极高。

## 3. 为什么拿不到“全部”

1. 阿里国际站**没有公开的省级企业目录**；搜索是商品/公司关键词匹配，不是地区枚举。
2. 单个关键词最多约 **400–500 家企业**（20 页 × 20 家），且无省过滤 → 要覆盖河北需要**海量关键词**（行业词 × 城市 × 县 × 产品词）。
3. 非地名公司（名字里没有 Hebei/城市/县）只能用产品词找到，再逐家详情判断省份 → **详情请求是瓶颈**（串行约 1 家/s，且大量请求会触发临时风控）。
4. 现有 1559 家已覆盖「地名可识别」的大部分；剩余是长尾，成本急剧上升。

## 4. 如果一定要更多：可行但昂贵的路线

| 方案 | 规模估算 | 时间/成本 | 预期收益 |
|---|---|---|---|
| **A. 行业词 × 城市矩阵 + 详情核验**（推荐先做） | 30–50 个河北支柱行业 × 11 城市 × 2 种关键词（如 “Hengshui wire mesh”/“安平丝网”）≈ 700–1100 次搜索，≥400 候选/次 → 20 万–40 万候选 | 搜索 ~0.5–1 天；详情核验（只对名称无法判定的）**数小时–数天**；需断点续跑 + 冷却 | 可能新增 1k–3k 河北企业（无法保证全量） |
| **B. 用新发现的 `/search/api/supplierTextSearch` 做候选采集** | 每关键词 20 页 × 20 家（JSON，不再解析 HTML） | 单关键词约 1–2 分钟，比 SSR 快 2–3 倍 | 只是提速，不解决覆盖 |
| **C. 外部数据**：海关/B2B 数据库、企业征信、Google/Bing site 检索、阿里官方数据服务 | — | 取决于数据源 | **唯一可能接近“全量”的路线** |

## 5. 建议

1. 接受当前口径：**3541 候选 → 1559 家已确认河北**（名称启发式 60/60 抽样准确）；报告里明确“可发现样本”而非“全部”。
2. 若继续投入，按「城市 × 行业」分批跑矩阵，每批控制预算（fetch budget 600/10min）、批间冷却、结果落库；先跑 Top 20 行业验证增量，再决定是否扩大。
3. 如需产品化：把矩阵采集做成 `ali sweep --matrix --province Hebei`（断点续跑 + 冷却 + 名称启发式 + 详情核验 + 导出 CSV）。
4. 完整性要求高的场景，建议走外部数据或阿里官方渠道，不要依赖前端搜索。
