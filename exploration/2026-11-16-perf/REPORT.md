# 河北省企业获取性能实测（2026-11-16）

> 目标：测量「获取河北省（可发现）企业」需要多久、能拿多少、能否优化。
> 环境：本机 systemd 常驻 + headful cloak 浏览器 + SQLite 缓存；`ALI_MAX_PAGES=20`、`ALI_FETCH_BUDGET_PER_10MIN=600`（批次调优值）。

## 1. 方法与口径

阿里国际站**没有**「按省列出全部企业」的目录接口，只有：
1. 关键词/城市名搜索（每页 20 家，平台只支持 `country=CN`，无省市筛选）；
2. 认证工厂目录（仅省、最多约 500 条）；
3. 公司详情（`shopSign/companyCard/companyOverview`）里才有权威省市。

因此「全省企业」采用**多种子搜索 + 名称启发式 + 详情回填**的采样口径：

| 组件 | 种子/策略 |
|---|---|
| 省份种子 | `Hebei`（20 页）、`河北`（10 页）、`河北省`（5 页） |
| 城市种子 | 河北 11 个地级市英文名（各 5 页） |
| 工厂目录 | 5 页 × 100 条，按 province 过滤 |
| 去重 | 按 `companyId` |
| 地点判定 | ① 公司名含河北/城市名 → 直接归类（名称启发式）；② 其他 → 详情回填；③ 抽样 60 家名称判定做详情核验 |

平台不提供「总共有多少家」，本结果只能代表**当前关键词组合下的可发现样本**。

## 2. 结果 A：第一版（14 种子，仅 11 个地级市）

> 注：第一版只用了「Hebei/河北/河北省 + 11 个地级市名」，未覆盖县级市/县，结果偏少。

| 指标 | 数值 |
|---|---|
| 候选去重 | **1147 家**（90 个搜索页 + 工厂目录扫描） |
| 河北企业 | **797 家** |
| 来源 | 名称判定 613 + 详情确认 180 + 工厂目录 4；地点未知 1 |
| 非河北（按名称/详情排除） | 约 340 家（江苏 118、广东 50、山东 30、浙江 30、重庆 26…） |
| 城市分布 | 邢台 134、石家庄 94、衡水 88、廊坊 67、邯郸 63、秦皇岛 58、唐山 48、张家口 20、保定 15、沧州 14、承德 7、未知 189 |
| 名称启发式抽样准确率 | **59/60 = 98.3%** |
| 耗时 | 工厂目录 7.3s + 搜索 **168.0s** + 详情 **377.3s** = **553s（约 9.2 分钟）** |
| 吞吐 | 搜索 6.8 候选/s（≈1.87s/页）；详情 0.53 家/s（串行、默认 2/700ms） |

## 2.5 结果 B：扩展种子（地级市 + 全部县级行政区）

针对「河北不止一千多家」的问题，扩展种子到**全部 11 个地级市 + 118 个县级行政区（县/县级市，排除区）**，并加深分页：

| 组件 | 策略 |
|---|---|
| 省级种子 | `Hebei` 20 页、`河北` 20 页、`河北省` 20 页 |
| 地级市种子 | 11 个城市 × 10 页 |
| 县级种子 | 118 个县/县级市（pinyin，1 页/个） |
| 名称启发式 | 增加县级地名（如 Anping/Qinghe/Ningjin… → 直接映射河北） |

| 指标 | 数值 |
|---|---|
| 种子数 | 129（3 省 + 11 市 + 115 县；去重后） |
| 候选去重 | **3541 家** |
| 名称启发式判定 | 2935 家（其中河北 1159） |
| 待详情确认 | 606 家 |
| 搜索耗时（cold） | **344s（5.7 分钟）**，吞吐 10.3 候选/s |
| **详情核验后河北企业** | **1559 家**（名称 1095 + 详情确认 460 + 工厂目录 4；未知 1） |
| 名称启发式抽样准确率 | **60/60 = 100%** |
| 详情耗时 | 665 次调用、592s、**1.12 家/s**、错误 1（budget 重试后完成） |
| 城市分布 | 衡水 213、石家庄 211、邢台 152、廊坊 130、唐山 106、保定 100、邯郸 70、沧州 62、秦皇岛 38、张家口 20、承德 16、仅省 441 |
| 冷启动总耗时 | ≈ 344s + 592s ≈ **15.6 分钟**（搜索 + 全部未知详情核验） |
| 缓存热跑 | 搜索 0.6s、详情命中后 <1s（第二轮） |

> 结论：**扩展县级行政区后，河北可发现企业从 797 提升到 1559（+96%）**。仍不是「全部」——平台没有省级企业目录，覆盖量取决于种子（可继续加行业词 × 城市/县）。

## 3. 对比与优化

| 方案 | 详情请求数 | 预计/实测耗时 | 说明 |
|---|---|---|---|
| 严格全量（每个候选都查详情） | 1147 / 3541 | 第一版 ≈39 分钟；扩展版 ≈55 分钟 | 未全跑（会超本地 budget 并触发风控） |
| **名称启发式（已实现）** | 200（含 60 抽样核验） | **9.2 分钟** | **4.2× 提速**，83% 详情请求被省掉 |
| 缓存热跑（同参数） | 0（全部命中） | 搜索 <1s、详情秒级 | 搜索 2h / 详情 7d TTL |
| 详情节流调参（2/700ms → 3/400ms，串行） | 254 | 详情 343s → **0.74 家/s（+40%）** | 仅调间隔有效 |
| 真并发详情（3 并发同页） | — | **失败**：请求 18s 挂起、UPSTREAM_TIMEOUT 90 次 | 上游对该接口并发敏感，已回退串行 |

**其他实测发现（已修复/已记录）：**
- 本地 fetch budget `240/10min` 在严格模式下会先于浏览器限频触发（76 次 `RATE_LIMITED`）；批次场景调到 **600/10min** 可完成一轮。
- 搜索缓存「最后一页不足 20 条」时应视为已抓完；否则每次都会重抓（已修复）。
- 工厂目录缓存键缺 `pageSize`，不同 pageSize 会串页（已修复）。
- 长时间空闲后 Chromium 会回收 worker 页 → `Target page closed`；已实现自动重建 worker 页。
- 详情接口在**持续高并发/高总量**后会进入「挂起」状态（18s watchdog 超时），重启服务、换 profile 都未立即恢复；搜索/工厂目录不受影响 → 属于上游对该接口的临时风控，需冷却数十分钟。

## 3.5 详情（render.htm）基准与调优（headless）

固定同一批候选（Hengshui 种子 96 家），每次 `refresh=true` 强制回源：

| 配置 | 样本 | 成功率 | 吞吐 | 平均/P50/P95 | 字段完整率 |
|---|---|---|---|---|---|
| 默认 串行 700ms | 40 | 40/40 | **1.09 家/s** | 914ms / 844ms / 1527ms | years/stars/products/location/membership 100% |
| 间隔 400ms（热身后） | 40 | 40/40 | 0.60 家/s | 1671ms / 903ms / 5346ms | 100% |
| 缓存命中（warm） | 40 | 40/40 | **482 家/s** | 2ms | 100% |

说明：400ms 那轮恰好遇到上游长尾（p95 5.3s、max 15.5s），吞吐反而下降；默认 700ms 在冷却后恢复到 1.09 家/s。**结论：不要盲目压低间隔，瓶颈在平台波动；批量分批 + 缓存最稳。**

另：详情真并发（3 并发同页）会触发上游 18s 挂起/熔断（已回退串行，并加连续超时熔断 10min）。

## 4. 结论与建议

1. **能拿多少**：在 14 个种子下可稳定发现 **~800 家河北企业**（含名称启发式判定，抽样准确率 98%）。这不是全省真实总数；要扩大覆盖需增加「行业词 × 城市」种子，并接受线性增长的抓取成本。
2. **需要多久**：扩展种子冷启动 ≈ **15.6 分钟**（搜索 5.7min + 详情核验 9.9min）；缓存热跑 <1 分钟。
3. **怎么优化**：
   - ✅ 名称启发式优先（省 83% 详情）→ 已实现于 `scripts/perf-hebei.mjs`；
   - ✅ 调 `ALI_DETAIL_INTERVAL_MS=400`（串行上限约 0.7-0.8 家/s）；
   - ✅ 批次预算 `ALI_FETCH_BUDGET_PER_10MIN=600`，避免中途 `RATE_LIMITED`；
   - ✅ 搜索页数：省级种子 20 页、城市种子 5 页、末页不足 20 条即停；
   - ❌ 不要开详情并发（>1 会触发上游挂起）；
   - ✅ 按城市分批、持久化结果、冷却后再跑下一批（防止详情接口被临时风控）；
   - ✅ 对最终高价值名单再做「逐家详情核验」，而不是全量核验。

## 4.5 更全覆盖路径探索（2026-11-16）

另行直接操控浏览器（不经 client）尝试了：URL 省市参数、UI Province 筛选、countrysearch 地区页、新版搜索 API（`supplierTextSearch` 等）、公司页推荐、手机站/sitemap、中文关键词、行业词等。**没有找到官方省级全量目录/可用省过滤**：省筛选值为空、API 不执行省过滤、地区页是关键词 SEO 页（3166 子域随机抽样河北率 0/19）。详见 [EXPLORATION-MORE.md](./EXPLORATION-MORE.md)。

结论：现有「关键词枚举 + 名称启发式 + 详情核验」仍是唯一可行路线；要更多只能做「行业词 × 城市」矩阵并接受数小时到数天的详情核验成本，或使用外部数据源。

## 5. 无头模式（headless）

- 已切到 `ALI_HEADLESS=true`：不再弹浏览器窗口；搜索/工厂/详情全部正常。
- 详情基准在 headless 下 40/40 成功；验证码/滑块需通过截图 + 坐标/自动拖动中继（`ali verify`）。
- 代码默认值已改为 headless=true（可用 `ALI_HEADLESS=false` 临时开窗口人工过验证）。

## 6. 复现

```bash
# 预置：systemd 服务运行、.env 中 ALI_MAX_PAGES=20, ALI_FETCH_BUDGET_PER_10MIN=600
npm run perf:hebei --                          # 基线（名称启发式 + 60 抽样核验）
node scripts/perf-hebei.mjs --deep --name-first --verify-sample 60
node scripts/perf-hebei.mjs --extended --name-first --verify-sample 60   # 129 种子扩展版
node scripts/detail-bench.mjs --n 40 --seed Hengshui --pages 5           # 详情基准（refresh）
node scripts/detail-bench.mjs --n 40 --seed Hengshui --pages 5 --warm    # 缓存命中
node scripts/perf-hebei.mjs --name-first --no-detail     # 只做快速清单
```

原始结果 JSON：`sweep-optimized-fresh.json`（797 家 cold）、`sweep-tuned-serial.json`（254 详情/0.74 家/s）、`sweep-warm-partial.json`（部分缓存 241s）。
