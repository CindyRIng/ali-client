## 4. 首次运行与登录

### 4.1 首次启动

```bash
ali serve --port 8792     # 前台调试：拉起 owner 浏览器 + REST（唯一持有 profile 的进程）
ali health                # 另一个终端；REST 未起时 CLI 会提示先 ali serve
ali status
```

首次启动会创建 `~/.ali-client/`、启动 Chromium、恢复 1 个 `www` worker 页并做一次 en-US/USD 初始化；耗时数十秒属正常【待实测】。生产常驻用 systemd（§9），不要长期前台跑；`status` 字段解读见 §5.1。

### 4.2 anonymous-first：默认不登录

✅ 第二轮实测：匿名与登录态的**搜索卡片字段集完全相同（35 字段）**；详情 `shopSign+companyCard+companyOverview` 全量匿名可得；工厂目录匿名可得。因此 v1 **登录不是前置条件**。

| 模式 | `meta.mode` / `status.loggedIn` | 可用能力 |
| --- | --- | --- |
| 匿名（默认） | `anonymous` / `false` | 搜索、翻页、详情、地区、工厂目录、缓存、验证 —— v1 全部只读能力 |
| 登录（可选） | `logged_in` / `true` | 在匿名能力之上保留买家侧会话；v1 数据不依赖登录 |

### 4.3 可选登录（人工 headful 一次）

```bash
ali login            # 打开/聚焦 owner 浏览器登录页；窗口内人工输账号 + 过滑块
ali login status     # 轮询：pending → logged_in / timeout / failed
```

- REST 等价：`POST /v1/session/login {"mode":"manual"}`（返回 `loginUrl`、`browserWindow:"shown"`、`timeoutMs:600000`）；`GET /v1/session/login/status` 轮询 `state/action/screenshotPath/expiresAt`。
- `action`：`solve_captcha`（先过滑块）/ `enter_credentials`（输账号）/ `none`；客户端**不处理密码**，只把窗口带到前台并回报状态；远程中继 v1.1 预留。
- ⚠️ 登录态是**会话级 cookie**：**关闭 owner 浏览器进程（含重启 `ali-client.service`）即掉登录**（本机复现 2 次）✅。profile 中的设备指纹与长期 cookie（`xman_f`/`xman_us_f`）保留，可降风控，但**登录态 v1 不持久**，重启后要用就重新登录。
- 掉线后读操作**自动降级匿名**（`meta.mode:"anonymous"` + `meta.warnings`），只读查询不中断。不要手动 `kill` Chromium。

### 4.4 人机验证（滑块）

| 项 | 实测/计划 |
| --- | --- |
| 触发条件 | **仅页面导航触发**：约 8–9 次快速导航/30s；fetch/XHR 150+ 次未触发 ✅ |
| `x5sec` 有效期 | 过验证后 **≈30 分钟**（实测 29.8min）；`status.risk.x5secExpiresAt` ✅ |
| 自动过验证 | 类人拖拽（缓动+抖动+回拉 1.5–2.5s）；失败 `reload()` 重试 ≤3 轮；实测最终 **3/3 成功**（首次 2/3）✅ |
| 人工兜底 | 失败返回 `CAPTCHA_REQUIRED` + `details.screenshotPath`；`ali verify` 看截图与 track/handle 坐标 |
| 远程中继 | `ali verify solve --mode drag --from 522,720 --to 780,720`（坐标基于 1920×1080 viewport）；`type:"qr"` 时人工扫码 |
| 冷却 | 连续 2 次失败进入冷却：`ALI_COOLDOWN_S`（默认 60s）+ `status.risk.cooldownUntil` |

```bash
ali verify                 # 是否有验证 + 截图路径 + 坐标
ali verify solve           # 自动拖拽
ali verify solve --mode drag --from 522,720 --to 780,720   # 远程/人工中继
```

### 4.5 fetch 挂起与 watchdog

风控态下 worker 页内 `fetch` **可能永不返回**（`AbortSignal` 无效）✅。必须依赖 Node 侧 watchdog：

- `ALI_WATCHDOG_MS=18000`（15–20s）；超时自动「导航目标 URL → 自动/人工过验证 → 重试一次 fetch」。
- 连续 2 次失败 → 冷却并返回 `CAPTCHA_REQUIRED`/`RATE_LIMITED`/`RISK_COOLDOWN`；`status.worker.fetchHealthy/lastFetchHungAt`、`status.risk` 可观测。
- **不要主动删 `x5sec`**；同 profile 单纯重启浏览器**不能**解除风控（绑 cookie/设备）✅，正确姿势是等冷却/过验证/必要时重登。

### 5.2 供应商搜索（核心）

```bash
# 关键词 + 省市（strict：详情回填精确过滤，默认）
ali search suppliers --keyword "led light" --province Hebei --city Hengshui --pages 2
# queryId   q_9f3c1a77b2e04d10
# location  Hebei / Hengshui (strict, matched 17, unknown 3, enriched 42/60)
# stats     raw 41 → deduped 39 (ads 1) → returned 17, detailCacheHits 12, 24.5s
# position companyId   companyName                        joinedYears stars plan
# 1        258180302   Hengshui Kangyuan Rubber ...        6           2     verified_supplier

# 无关键词：地点词当 keywords（快速）；off 模式只按关键词
ali search suppliers --province Hebei --city Hengshui --location-mode keyword --pages 1
ali search suppliers --keyword "solid tire" --location-mode off --pages 1
```

| 参数 | 说明 |
| --- | --- |
| `--keyword/-k <kw>` | 关键词；与省市至少给一个 |
| `--province <name>` / `--city <name>` | 省（中文/英文/拼音/GB 代码）/ 市（需省或可反查父级） |
| `--location-mode strict\|keyword\|off` | 缺省：有省市=`strict`，否则 `off` |
| `--include-unknown-city` / `--exclude-unknown-city` | 城市未知是否保留（默认保留，标 `locationConfidence:"low"`） |
| `--pages <n>` | 本次预抓页数，默认 5（`ALI_MAX_PAGES`），硬上限 20；以「返回 0 条」终止（`totalCount` 不可靠） |
| `--max-enrich <n>` | strict 回填上限，默认 60（`ALI_MAX_ENRICH`） |
| `--verified-supplier` / `--verified-pro` / `--trade-assurance` | `assessmentCompany=true` / `verifiedPro=1` / `ta=y` |
| `--min-review <4\|4.5\|5>` | 店铺评分下限（`reviewScore`） |
| `--company-auth <tag,...>` / `--product-auth <tag,...>` | 认证筛选（如 `ISO,BSCI` / `CE`） |
| `--capability <name,...>` / `--sort <type>` | 能力标签（`tagKvPairIntFilter`）/ 结果排序 |
| `--refresh` | 绕过读缓存并覆盖写回 |

返回 `data`：`queryId`、`effectiveKeyword`、`location{requested,normalized,mode,enrichedCompanies,matched,unknownLocation,limitReached}`、`pages[]`、`suppliers[]`、`stats{totalCount,rawItems,deduped,ads,returned,detailRequests,detailCacheHits,enrichLimitReached}`。strict 逐条调详情回填（缓存优先），**慢是预期**；达到上限时 `meta.warnings` 标 `ENRICH_LIMIT_REACHED`。

### 5.3 翻页 / 详情

```bash
ali suppliers list --query-id q_9f3c1a77b2e04d10 --page 2
# page 2 pageSize 20 hasMore true fetchedPages [1,2]

ali suppliers detail --company-id 258180302
ali suppliers detail --store kangyuanxiangsu      # 由 search 结果 action 的子域推导
```

已完成 strict 过滤，`list` 返回该页**过滤后**结果（可能 <20 条）；未预抓页返回 `PAGE_NOT_AVAILABLE`（提高 `--pages`/`--refresh`）。

| 详情字段 | 说明 |
| --- | --- |
| `companyId/companyName/storeUrl/logoUrl` | 基础标识 |
| `location` | `province/city/address/confidence/source`（`shopSign` 回填） |
| `joinedYears` + `joinedYearsText` | 入驻年限（`companyJoinYears`，`"6 yrs"` 归一化） |
| `supplierIndex.stars` | **Supplier Index 星级 0–5**（=`shopSign.supplierStars`，≠ `reviewScore`） |
| `mainProducts.list/text` | 主营产品 |
| `businessType` / `identity` | 工厂/贸易商；`strengthFactory`=Custom Manufacturer（身份≠档位） |
| `membership` | `plan`（`verified_pro`>`verified_supplier`>`gold_supplier`>`unknown`）+ 证据 |
| `profile` | 成立年份/年营收/员工/主要市场/付款交货条款/简介（`companyOverview`） |

## 6. REST 部署与调用

> 【待实现】端点/鉴权/错误码与 [02 §0/§7](./02-接口草案.md) 同源，最终以 `spec/openapi.json` 为准。

```bash
ali serve --port 8792        # 端口默认 ALI_PORT=8792；只监听 127.0.0.1
export ALI_API_TOKEN=$(grep -E '^ALI_API_TOKEN=' ~/ali-client/.env | cut -d= -f2-)
```

- **只监听 loopback**；不要 `0.0.0.0`、端口转发或公网反代。
- 除 `/v1/health`、`/docs`、`/openapi.json`、`/mcp-tools.json` 外均需 `Authorization: Bearer $ALI_API_TOKEN`；响应带 `X-Ali-Cached`/`X-Ali-Mode`，限频带 `Retry-After`。
- 响应统一 envelope `{ok,data,meta,error}`；错误含 `code/message/retryable/details`。

**端点清单**：`GET /v1/health`、`GET /v1/status`、`POST /v1/session/login`、`GET /v1/session/login/status`、`GET /v1/verification`、`POST /v1/verification/solve`、`GET /v1/regions`、`GET /v1/regions/search`、`POST /v1/search/suppliers`、`GET /v1/suppliers?queryId=&page=`、`GET /v1/suppliers/{companyId}`、`GET /v1/factories`、`GET /v1/meta/memberships`、`GET /v1/cache/stats`、`DELETE /v1/cache?kind=`、`POST /v1/cache/prune`（P1）、`GET /v1/verification/screenshot`、`GET /docs`、`GET /openapi.json`、`GET /mcp-tools.json`。

```bash
H="Authorization: Bearer $ALI_API_TOKEN"
curl -s http://127.0.0.1:8792/v1/health | jq .
curl -s -H "$H" http://127.0.0.1:8792/v1/status | jq '.data.mode,.data.risk'
```

```json
{ "ok": true, "data": { "queryId": "q_9f3c1a77b2e04d10" },
  "meta": { "schemaVersion": "1.0", "mode": "anonymous", "cached": false, "queryId": "q_9f3c1a77b2e04d10", "elapsedMs": 24500, "serverTime": "2026-11-15T14:20:00+08:00" },
```

失败时 `ok:false`、`data:null`、`meta.mode` 保留、`error:{code,message,retryable,details}`。错误码：`INVALID_ARGUMENT`(400)、`UNAUTHENTICATED`(401)、`NOT_FOUND`(404)、`LOGIN_REQUIRED`(409)、`CAPTCHA_REQUIRED`(409)、`RATE_LIMITED`(429)、`UPSTREAM_ERROR`(502)、`UPSTREAM_TIMEOUT`(504)、`PAGE_NOT_AVAILABLE`(409)、`BAD_STATE`(409)、`NOT_IMPLEMENTED`(501)、`INTERNAL_ERROR`(500)；`RISK_COOLDOWN`(409，冷却中，含 `details.cooldownUntil`)；`ENRICH_LIMIT_REACHED` 以 200 + `meta.warnings` 表达（详见 02 §0.3/§20）。

- 用户级服务默认只在登录会话中运行；希望**开机/未登录也常驻**：`loginctl enable-linger $USER`。
- **重启语义**：重启服务 = 关闭 owner 浏览器 = **登录态丢失**（会话级 cookie）✅；anonymous-first 下只读查询不受影响，需要登录态时重新 `ali login`。缓存不受影响，重启后毫秒级命中。

- **无桌面**：先起 `Xvfb :99 -screen 0 1920x1080x24`，unit 用 `DISPLAY=:99`；人工登录需远程桌面/中继协助，v1 不保证风控表现与真实桌面一致【待实测】。

## 10. 数据目录与运维

```text
~/.ali-client/
├── profile/                  # Chromium userDataDir（登录态/设备指纹） 0700
├── cache.sqlite              # SQLite 结构化缓存（WAL） 0600；另有 -wal/-shm
├── logs/ali-YYYYMMDD.log     # JSONL 运行日志（按天轮转） 0600
├── run/ali.lock              # 单实例锁
├── run/captcha-*.png         # 滑块截图（≈30 分钟后清理） / login.png 登录中继截图
└── tmp/                      # 中继临时文件（可清）
```

- 缓存**只存结构化字段**：不落 HTML、cookie、token、验证码图片。探路遗留的 `~/.ali-client/profile-anon` 可删除，勿与生产 `profile/` 混用。
- **TTL**：搜索 query 2h（`ALI_TTL_SEARCH_S=7200`）｜详情 7d（`ALI_TTL_DETAIL_S=604800`，与 strict 回填共用）｜工厂目录 24h（`ALI_TTL_FACTORY_S=86400`）｜地区字典静态（≈365d）。`cache.stats` 看命中率/字节；过期行惰性清理 + 启动 prune。

```bash
# 备份（停服务后复制，避免 WAL/锁不一致；含登录/指纹信息，按 600 保存）
systemctl --user stop ali-client
tar -czf ~/ali-backup-$(date +%F).tar.gz -C ~ .ali-client/cache.sqlite .ali-client/profile .ali-client/logs
systemctl --user start ali-client

# 只清缓存（不丢登录态/设备指纹）：CLI 或停服务后重建
ali cache clear --kind all
systemctl --user stop ali-client && rm -f ~/.ali-client/cache.sqlite* && systemctl --user start ali-client
```

- 备份 `profile/` 可保留设备指纹与长期 cookie，但**会话级登录态不随备份/重启恢复**（v1 需重新登录）；只清 `profile/` 不影响缓存，反之亦然。
- **日志轮转**：JSONL 写 `~/.ali-client/logs/`，**按天轮转**（`ali-YYYYMMDD.log`）；保留份数/大小上限实现时回填【待实现】；journald 侧用 `journalctl --since`/磁盘限额管理。
- **单实例锁**：`run/ali.lock`（REST/app）与 `profile/SingletonLock`（Chromium）。冲突表现 `BAD_STATE`；恢复：停服务 → `pgrep -af 'ali\|chromium'` 确认无进程 → 再删锁，**不要在进程存活时删**。
- **权限**：`chmod 700 ~/.ali-client{/profile,/logs,/run}`、`chmod 600 cache.sqlite logs/*.log ~/ali-client/.env`；用 `stat -c '%a %U %n'` 核对。

| # | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 0 | **`ali: command not found`** | 未注册命令或 `~/.local/bin` 不在 PATH | `ln -sfn "$PWD/bin/ali-run" ~/.local/bin/ali`；确认 `echo $PATH` 含 `~/.local/bin` |
| 0b | **改了代码但行为没变** | 常驻进程仍加载旧 `dist/` | `npm run build && systemctl --user restart ali-client` |
| 0e | **`error [UNAUTHENTICATED]: invalid token`** | CLI 未加载到仓库 `.env`（从其它目录运行/未设置 `ALI_ENV_FILE`/token 改过） | 已修复：`bin/ali-run` 会自动加载仓库 `.env`；也可 `export ALI_API_TOKEN=...` 或 `export ALI_ENV_FILE=/path/to/.env` |
| 0f | **服务被外部进程 kill 后不可用** | 以前 unit 仅 on-failure；clean exit 不拉起 | v0.1.0 起 `Restart=always`（等 3s 自动恢复），`StartLimitIntervalSec=0` 避免频繁重启进入 failed |
| 0g | **REST 参数校验返回 422** | `VALIDATION_FAILED` → 422；业务参数非法（如未知省份）→ 400 `INVALID_ARGUMENT` | 按语义处理即可 |
| 0c | **`ali serve` 提示已在运行** | 已有存活 owner（owner 锁 `~/.ali-client/run/ali.lock`，与端口无关） | 正常行为；直接用 `ali ...`，勿再手动跑第二个 owner。`--local` 同样会被锁拒绝（`BAD_STATE`，exit 3） |
| 0d | **`ali verify solve` 报 CAPTCHA_FAILED（no active captcha）** | 当前没有滑块挑战 | 正常；有滑块时先 `ali verify status` 查看截图/坐标 |
| 1 | **滑块反复出现** | 导航过密（8–9 次/30s）、`x5sec` 过期、风控升级、headless | 保持 fetch-first；调大 `ALI_PAGE_INTERVAL_MS`（默认 10000）；`ali verify`→`ali verify solve`；失败等冷却；不要主动删 `x5sec` |
| 2 | **fetch 挂起不返回** | 风控态 fetch 永不返回且 `AbortSignal` 无效 | 内置 watchdog（`ALI_WATCHDOG_MS=18000`）自动「导航→过验证→重试」；`ali status` 看 `worker.fetchHealthy/lastFetchHungAt`、`risk.cooldownUntil`；仍不行人工中继 |
| 3 | **登录掉线** | 会话级 cookie，浏览器进程关闭即掉 | 不需要登录就别登；需要则重启后 `ali login`；不要手动 kill Chromium；`ali status` 确认 `mode` |
| 4 | **端口冲突**（`EADDRINUSE`/连不上） | 8792 被占，或 `ALI_API_URL` 指向错误端口 | `ss -tlnp \| grep 8792`；释放或改 `ALI_PORT` 并同步 `ALI_API_URL` 与客户端配置 |

| 6 | **权限/沙箱报错**（chrome-sandbox、bwrap） | 宿主直接跑 Chromium、user namespaces 受限、权限不当 | 一律用 `bin/ali-run`（进 FHS）；不要 root 运行；检查 userns；不要长期 `--no-sandbox`（见 04 §13） |
| 7 | **限频 429/`RATE_LIMITED`、`RISK_COOLDOWN`** | 本地限频/上游冷却/连续恢复失败 | 按 `retryAfterMs`/`cooldownUntil` 退避；调大页/详情间隔；必要时重启服务；降 `pages`/`maxEnrich` |
| 8 | **搜索慢（几十秒）** | strict 逐条详情回填（0.3–0.8s/家、并发 2、上限 60），冷查询无缓存 | 先用 `--location-mode keyword`；调小 `--pages`/`--max-enrich`；二次查询走缓存；看 `stats.detailCacheHits` |
| 9 | **城市过滤结果少/为空** | 平台无省市筛选，strict 靠详情回填；部分地址缺城市 | 保留默认 `includeUnknownCity=true`（未知标 `low`）；城市名先 `ali regions search` 归一化；或改 `keyword` 模式放宽 |
| 10 | **缓存不一致/旧数据** | TTL 内返回缓存、未传 `refresh` | `--refresh`/`refresh=true` 强制回源；`ali cache clear --kind queries\|details`；搜索 2h、详情 7d、工厂 24h |
| 11 | **二维码验证/远程无桌面** | 子域风控升级转 QR 兜底 | `ali verify` 取截图人工扫码；远程用 `--from/--to` 坐标中继；本机 headful 最稳 |
| 12 | **磁盘满/SQLite 忙** | WAL 增长、日志膨胀、空间不足 | `df -h ~`、`du -sh ~/.ali-client/*`；`cache clear`；停服务后清日志与临时截图；确认无两个进程写同一 DB |

## 14. 安全与合规

- **只监听 loopback**：REST 固定 `127.0.0.1:8792`；不 `0.0.0.0`、不端口转发/公网反代；远程用本机 MCP/CLI 或 SSH 隧道。
- **Bearer 鉴权**：`ALI_API_TOKEN` 用 32 字节随机串；`.env` 600；泄漏即轮换并重启；MCP 客户端配置避免明文入库。
- **不落敏感**：缓存不存 HTML/cookie/token/验证码图片；滑块截图仅临时文件（≈30 分钟清理）；日志脱敏（不记录密码、cookie、token、二维码原文）。
- **只读**：不询盘/聊天/收藏/下单/写卖家后台，只抓公开页面/接口。
- **低频**：导航 ≥10s、fetch 0.8–1.2s、详情并发 2；风控升级即冷却，不绕过、不破解。

**C. 错误码速查**（详见 [02 §0.3](./02-接口草案.md)）

| code | HTTP | 处理建议 |
| --- | --- | --- |
| `INVALID_ARGUMENT` | 400 | 省市归一化失败/参数非法：先 `ali regions search`，多义用全名 |
| `UNAUTHENTICATED` | 401 | Bearer 缺失/错误：核对 `ALI_API_TOKEN` |
| `NOT_FOUND` | 404 | 对象不存在：重新搜索或 `refresh` |
| `LOGIN_REQUIRED` | 409 | 上游要求登录：`ali login`（v1 极少） |
| `CAPTCHA_REQUIRED` | 409 | `ali verify`/`solve`；失败转人工中继 |
| `RATE_LIMITED` | 429 | 按 `retryAfterMs` 退避、等冷却 |
| `RISK_COOLDOWN` | 409 | 连续失败进入冷却：等 `details.cooldownUntil`，必要时重启服务 |
| `UPSTREAM_ERROR` / `UPSTREAM_TIMEOUT` | 502/504 | 可重试；持续则查网络/上游改版 |
| `PAGE_NOT_AVAILABLE` | 409 | 提高 `pages` 或 `refresh` 后重试 `list` |
| `BAD_STATE` | 409 | 浏览器/profile 异常：FAQ #5 恢复 |
| `NOT_IMPLEMENTED` | 501 | v1.1 功能（如 batch），降级到 v1 操作 |
| `ENRICH_LIMIT_REACHED` | 200+warning | 结果可能不全：缩小范围或调大 `maxEnrich` |
