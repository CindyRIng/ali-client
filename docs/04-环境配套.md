# ali-client 环境配套

> 本文说明 `ali-client` 依赖的**本机共享运行环境**：`~/cloak-env`（FHS + Chromium + cloakbrowser）、Node 版本、`~/.cloakbrowser` 缓存、DISPLAY/XWayland、profile 隔离、依赖锁定与 NixOS 注意事项。
> 部署步骤与日常使用见 [03-部署与使用.md](./03-部署与使用.md)；上游字段/链路实测见 [REPORT.md](../exploration/2026-11-15/REPORT.md)。

## 1. 目的与适用范围

- 本机（NixOS 26.11，单用户 `songqian`）已有多个同构客户端（`tanji-client` / `boss-client` / `zhilian-client`）与共享环境 `~/cloak-env`；`ali-client` **只复用、不修改**这套共享环境。
- 本文给出：共享环境结构与版本、`cloak-run` 用法、显示/会话约束、profile 隔离、本机端口与数据目录占用、计划依赖与目录结构、`.env` 全量变量、NixOS 注意项、采集环境约束、常见环境问题。
- 不适用：非 NixOS 宿主、公网/多租户部署、无桌面且无法中继人工验证的场景（降级见 03 §4/§9）。
- 标注约定：✅ 实测（2026-11-15 本机真实探测/探路）｜📐 设计｜【待实现】当前仓库尚无代码｜【待实测】实现后回填。**本文所有路径/版本以本机实测为准；命令按计划编写，实现后需核对。**

| 组件 | 位置 | 谁维护 | ali-client 的动作 |
| --- | --- | --- | --- |
| 共享 FHS + Node | `~/cloak-env` | 人工（`nix build` / `npm install`） | 只读调用 `bin/cloak-run`；不删不改 |
| Chromium 二进制缓存 | `~/.cloakbrowser` | cloakbrowser 首次运行时自动下载 | 只读复用；运行中不删 |
| 项目代码与配置 | `~/ali-client` | git / npm / 人工 | 本项目自己的文件 |
| 运行时数据 | `~/.ali-client` | 进程自动写入 | 独立 profile/缓存/日志/锁 |
| 图形会话 | XWayland `DISPLAY=:0` | 桌面环境 | headful 常驻（登录/过验证） |

**四条共享原则**：① FHS 与浏览器二进制共享；② **profile 每个项目独立**（禁止共用 `userDataDir`）；③ 依赖版本每个项目在 `package.json` 精确锁定（不依赖 `NODE_PATH`）；④ 业务缓存/日志/锁全部放在各自 `~/.<project>`。

## 2. `~/cloak-env` 结构

```text
~/cloak-env/
├── fhs.nix                     # FHS 构建表达式（buildFHSEnv；nodejs_22 + Chromium 运行库）
├── cloak-fhs -> /nix/store/<hash>-cloak-fhs   # nix build 输出（-o 建立的 GC root）
├── package.json                # cloakbrowser 0.6.5 + playwright-core 1.65.0
├── package-lock.json
├── node_modules/
├── bin/cloak-run               # 通用入口：进入 FHS 后执行命令（保持当前目录）
├── bin/cloak-env-info          # 版本/路径信息
├── README.md                   # 共享环境说明（重建/升级/共用约定）
└── tmp-*.mjs                   # 历史探针脚本（可忽略，非共享环境组成部分）
```

| 条目 | 作用 | 说明 |
| --- | --- | --- |
| `fhs.nix` | FHS 构建表达式 | `buildFHSEnv`；`targetPkgs` 含 `nodejs_22` 与 Chromium 所需图形/字体库；`allowUnfree = true` |
| `cloak-fhs` | FHS 根（symlink） | 指向 `/nix/store/...-cloak-fhs`；`-o` 建立 GC root，`nix-collect-garbage` 后仍有效 |
| `package.json` / `package-lock.json` | 共享依赖清单 | 精确锁 `cloakbrowser: 0.6.5`、`playwright-core: 1.65.0` |
| `node_modules/` | 共享 npm 包 | 项目**不**通过 `NODE_PATH` 复用；在各自 `package.json` 锁同版本（ESM 不识别 NODE_PATH） |
| `bin/cloak-run` | 进入 FHS 执行命令 | 本项目 `bin/ali-run` 依赖它；见 §4 |
| `bin/cloak-env-info` | 版本/路径探测 | 输出 `cloak-env`、`fhs`、`cloakbrowser`、`playwright-core` 版本 |
| `README.md` | 共享环境手册 | 重建 FHS、升级 cloakbrowser、其他项目共用约定 |

> `~/cloak-env` 在项目之外、供多客户端共用：**不要**因 `ali-client` 需要而修改 `fhs.nix` 或升级共享依赖；要升级先评估全部客户端（§3/§8）。

## 4. `cloak-run` 用法

### 4.1 脚本行为（实测，`~/cloak-env/bin/cloak-run`）

- 解析脚本真实路径得到 `ROOT=~/cloak-env`；FHS 取 `${CLOAK_FHS:-$ROOT/cloak-fhs}`。
- 无参数 → 打印 usage，退出码 **2**；`$FHS/bin/cloak-fhs` 不可执行 → 提示重建并退出码 **127**。
- 工作目录：`${CLOAK_WORKDIR:-$PWD}`（**默认保持当前目录**；已实测 FHS 内 `PWD` 不变）。
- 显示：`export DISPLAY="${DISPLAY:-:0}"`（宿主未设置 DISPLAY 时默认 `:0`）。
- 参数逐字节转义后用 `exec "$FHS/bin/cloak-fhs" -c "cd '$WORKDIR' && exec <command...>"` 执行，退出码透传。
- 因此**不需要**知道 `/nix/store/<hash>` 路径：项目脚本只调用 `~/cloak-env/bin/cloak-run`，FHS 重建后 symlink 更新即可。

### 4.2 常用形式

```bash
~/cloak-env/bin/cloak-run node dist/main.js                 # 当前目录执行（默认）
CLOAK_WORKDIR=/path/to/proj ~/cloak-env/bin/cloak-run node dist/main.js   # 指定工作目录
CLOAK_FHS=/opt/cloak-fhs ~/cloak-env/bin/cloak-run node -v               # 指向其他 FHS 根
DISPLAY=:0 ~/cloak-env/bin/cloak-run node dist/main.js                  # 显式指定显示
```

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CLOAK_FHS` | `~/cloak-env/cloak-fhs` | FHS 根；指向错误会 `FHS not found`（退出码 127） |
| `CLOAK_WORKDIR` | 当前目录 `$PWD` | 进入 FHS 后的工作目录 |
| `DISPLAY` | 继承宿主；未设置时 `:0` | X/Wayland 显示；headful 必需 |
| `CLOAK_ENV` | `~/cloak-env` | **本项目 `bin/ali-run` 层**的共享环境根（不是 `cloak-run` 自身的变量） |

### 4.3 FHS 内实测验证

```bash
~/cloak-env/bin/cloak-run node --version                          # v22.23.2
~/cloak-env/bin/cloak-run sh -c 'ls /lib64/ld-linux-x86-64.so.2'  # 存在（Chromium 可加载动态库）
~/cloak-env/bin/cloak-run ls /tmp/.X11-unix                       # 可见 X0（宿主 /tmp 对 FHS 可见）
~/cloak-env/bin/cloak-run sh -c 'echo $DISPLAY; pwd'              # :0；当前目录保持不变
```

- `/tmp/.X11-unix/X0` 在 FHS 内可见 → `DISPLAY=:0` 可直接连宿主 XWayland；若自定义隔离环境导致 socket 不可见，Chromium 会报 `Missing X server or $DISPLAY`（见 §13）。
- `/lib64/ld-linux-x86-64.so.2` 等在 NixOS 宿主不存在、FHS 内存在——这就是必须经 `cloak-run` 启动浏览器的原因。

### 4.4 `bin/ali-run`（计划包装脚本）

```bash
#!/usr/bin/env bash
# 通过共享 cloak-env 的 FHS 运行 ali-client（供 systemd / 全局 ali 命令调用）
set -euo pipefail
SELF="$(readlink -f "${BASH_SOURCE[0]}")"; ROOT="$(cd "$(dirname "$SELF")/.." && pwd)"
CLOAK_ENV="${CLOAK_ENV:-$HOME/cloak-env}"; cd "$ROOT"
if [ -x "$CLOAK_ENV/bin/cloak-run" ]; then exec "$CLOAK_ENV/bin/cloak-run" node dist/main.js "$@"; fi
exec node dist/main.js "$@"   # 无 cloak-env 时直跑（仅适合 health/docs 等不启浏览器的命令）
```

> 【待实现】与 `zhilian-run`/`boss-run` 同构；`CLOAK_ENV` 可覆盖共享环境路径。MCP（默认代理 REST、不启浏览器）可直接 `node dist/main.js mcp`，不必进 FHS。

## 5. 显示与会话

本机实测：Wayland 会话 + **XWayland**，`DISPLAY=:0`、`WAYLAND_DISPLAY=wayland-1`、`/tmp/.X11-unix/X0` 存在。

| 维度 | headful（计划默认） | headless |
| --- | --- | --- |
| 滑块触发 | 较低（探路全程 headful，fetch 150+ 次无滑块）✅ | 连发 2–3 个页面即触发 ✅ |
| 人工登录/过验证 | 可（owner 浏览器窗口） | 不可 |
| 自动拖拽成功率 | 探路 3/3 最终成功 ✅ | 未验证，预期更差【待实测】 |
| 资源/依赖 | 需要 DISPLAY；内存占用更高 | 无需显示 |
| 适用 | 本机常驻（`ALI_HEADLESS=false`） | 无桌面只读尝试；登录/兜底仍需 headful |

**结论**：计划默认 `ALI_HEADLESS=false`。fetch-first 已把风控暴露面压到最低（导航才触发验证），但**登录、自动/人工过验证、坐标中继**都需要真实渲染，headful 是本机常驻的推荐形态。

**会话模型**：owner 浏览器常驻 + 只保留 1 个 `https://www.alibaba.com/` worker 页；登录态是**会话级 cookie**——**关闭浏览器进程即掉登录**（本机复现 2 次）✅，因此进程必须常驻（systemd）；重启服务等于掉登录（anonymous-first 下不影响只读查询，见 03 §4.3）。

**无显示/远程部署**：

```bash
Xvfb :99 -screen 0 1920x1080x24 &
export DISPLAY=:99
```

- 可在 Xvfb 下 headful 运行，但**风控观感与真实桌面可能不同**（v1 不保证）【待实测】；
- 人工登录用远程桌面，或走「截图 + 坐标/二维码 REST/MCP 中继」（03 §4.4）。

**分辨率/时区**：viewport **1920×1080**（`verification.track/handle` 坐标以此为准，见 02 §2.4）；浏览器 timezone **Asia/Shanghai**，服务端时间 ISO 8601 `+08:00`。改分辨率需同步坐标换算与截图标注。

## 6. profile 隔离

- 默认 **`~/.ali-client/profile`**（`ALI_PROFILE_DIR` 可改），由 `launchPersistentContext({ userDataDir })` 独占持有。
- **禁止共用 profile**：cookie、设备指纹、风控状态会互相污染；两个进程抢同一 `userDataDir` 会 `SingletonLock` 冲突。`~/cloak-env` README 的共用约定同样要求「每个项目/账号独立 profile」。

| 项目 | profile 路径 | 数据目录 |
| --- | --- | --- |
| **ali-client** | `~/.ali-client/profile` | `~/.ali-client` |
| zhilian-client | `~/.zhilian-client/profile` | `~/.zhilian-client` |
| boss-client | `~/.boss-client/profile` | `~/.boss-client` |
| tanji-client | `~/.tanji-client/...`（按账号） | `~/.tanji-client` |

**登录态与 profile**：

- 登录态依赖会话级 cookie（`x5sec`、登录 token 等），关闭浏览器进程即掉；profile 中保留**设备指纹与长期 cookie**（`xman_f`/`xman_us_f`），可降低再次登录/验证时的风控强度，但**不能让登录态跨进程保留**（v1 如实降级匿名，不伪装已登录）。
- 探路阶段在 `~/.ali-client/profile-anon` 留下过一个匿名探索 profile，可删除；**不要**把它当生产 profile 用。

**profile 锁与恢复**：

```bash
systemctl --user stop ali-client
pgrep -af 'ali-client|chromium'          # 必须确认没有 ali 相关进程持有 profile
rm -f ~/.ali-client/profile/SingletonLock ~/.ali-client/run/ali.lock
systemctl --user start ali-client
```

- **进程存活时不要删锁**；先停服务、确认进程退出，再清 `SingletonLock`/`ali.lock`。
- 备份/清理 profile 一律停服务后操作；profile 含登录/指纹等同凭证，权限 **0700**、备份文件 **600**、不入库不外发。
- 只清 `profile/` 丢登录态与指纹（需重登，短期风控更敏感）；只清 `cache.sqlite` 不影响登录。

## 11. NixOS 注意

- **为什么需要 FHS**：NixOS 宿主没有 `/lib64/ld-linux-x86-64.so.2` 等通用路径，而 cloakbrowser 的 Chromium 是通用 Linux 二进制；`~/cloak-env/fhs.nix` 用 `buildFHSEnv` 提供兼容根，`bin/cloak-run` 进入后执行。
- **重建 FHS（含 GC root）**：

```bash
cd ~/cloak-env
NIXPKGS_ALLOW_UNFREE=1 nix build --impure --expr 'import ~/cloak-env/fhs.nix' -o ~/cloak-env/cloak-fhs
~/cloak-env/bin/cloak-env-info
```

`fhs.nix` 内部已 `allowUnfree = true`；显式 `NIXPKGS_ALLOW_UNFREE=1` 与共享 README 的调用方式保持一致。`-o ~/cloak-env/cloak-fhs` 建立 GC root，避免 `nix-collect-garbage` 后 symlink 指向失效路径。

- **nix store 路径稳定性**：重建会生成新的 `/nix/store/<hash>-cloak-fhs`，`cloak-fhs` symlink 随之更新；因此**不要在 systemd unit / 脚本里硬编码 `/nix/store/...`**，一律走 `bin/cloak-run`。
- **沙箱（bwrap / user namespaces）**：Chromium 需要 user namespaces/沙箱支持。若报 `No usable sandbox`、bwrap 相关错误，优先检查 FHS 完整性、运行用户非 root、内核/发行版是否允许非特权 user namespaces；**不建议长期 `--no-sandbox`**（降低隔离且易被上游识别）。见 §13。
- **Chromium 缓存共享**：`~/.cloakbrowser` 是用户级缓存，所有客户端天然共享（`chromium-146.0.7680.177.5`）；不要重复下载/删除缓存目录，运行中删除会导致浏览器崩溃。
- **权限**：`~/.ali-client` 及其 `profile/`、`logs/`、`run/` 为 **0700**；`cache.sqlite`、日志、`.env` 为 **0600**。多人机器注意 umask。
- **systemd 用户级**：开机自启需 `loginctl enable-linger $USER`（见 03 §9）；unit 里用 `%h` 展开 home，不要写死用户名。
- **时间同步**：`x5sec` 有效期、滑块/风控与本地时间相关；保持 NTP（`timedatectl status` 显示 synchronized）。
- **运行位置**：浏览器与采集必须在 `cloak-run` 的 FHS 内；宿主 Node 只用于 `npm run build`/`npm test` 等不启浏览器的命令。

## 13. 常见环境问题与修复

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| `cloak-run: FHS not found at ...`（退出码 127） | `cloak-fhs` 缺失或 GC root 失效 | 按 §11 重新 `nix build ... -o ~/cloak-env/cloak-fhs` |
| `Cannot find package 'cloakbrowser'` | 未在 FHS 内运行，或项目 `node_modules` 未安装 | 用 `bin/ali-run`；`cd ~/ali-client && npm install` |
| `Missing X server or $DISPLAY` / 浏览器起不来 | DISPLAY 未设置或 X socket 不可见 | `export DISPLAY=:0`；`ls /tmp/.X11-unix`；无桌面用 `Xvfb :99`（§5） |
| 浏览器启动即退出 | Chromium 缓存/FHS/显示/崩溃残留 | `~/cloak-env/bin/cloak-env-info`；确认 `~/.cloakbrowser` 完整；停服务后清 `profile/Crashpad/` |
| `SingletonLock` / profile 被占用 | 多进程抢同一 `userDataDir` | §6 恢复：停服务 → 确认无进程 → 删锁 → 重启 |
| crashpad 报错刷屏（`chrome_crashpad_handler`） | 上次异常退出残留 | 停服务后清理 `profile/Crashpad/` 与 `profile/SingletonLock`，再启动 |
| `No usable sandbox` / chrome sandbox 报错 | user namespaces 受限、root 运行、FHS 不完整 | 用 `cloak-run` 非 root 运行；检查内核 userns 配置；不要长期 `--no-sandbox` |
| 磁盘空间不足 / 启动失败 | 缓存/日志/多版本 Chromium 占满 | `df -h ~`、`du -sh ~/.cloakbrowser ~/.ali-client`；`cache clear`；清旧日志；只留当前 Chromium 版本目录 |
| DNS/TLS 报错（`getaddrinfo`/证书） | 网络/代理/系统时间 | `curl -sI https://www.alibaba.com/`；检查 `http_proxy/https_proxy`；`timedatectl`；系统 CA |
| Chromium 首次启动很慢 | 正在下载 Chromium 到 `~/.cloakbrowser`（约 697MB） | 等待/检查网络；失败重试 |
| `node:sqlite` ExperimentalWarning | Node 22 对内置 SQLite 的提示 | 正常，可忽略；不影响功能 |
| X11 socket 在 FHS 内不可见 | 自定义 FHS/隔离环境未共享 `/tmp/.X11-unix` | 用标准 `~/cloak-env/bin/cloak-run`；确认宿主 `/tmp/.X11-unix/X0` 存在 |
| 时间/时区不对导致验证异常 | NTP 未同步、时区配置错误 | `timedatectl status`；同步时间；浏览器时区固定 `Asia/Shanghai` |

## 14. 安全隔离与合规

- **共享环境只读**：不修改 `~/cloak-env`、不删除 `~/.cloakbrowser`、不与其他项目共用 profile。
- **数据隔离**：profile/cache/logs/run 全部在 `~/.ali-client`；不同项目之间不交叉读写。
- **权限**：`~/.ali-client` 0700、`profile/` 0700、`cache.sqlite`/日志/`.env` 0600；备份 profile 等同凭证，按 600 保存、不入库不外发。
- **REST 只 loopback + Bearer**：不暴露公网、不端口转发；token 随机 32 字节并定期轮换。
- **不落敏感**：不持久化 HTML/cookie/token/验证码图片；滑块截图仅临时文件（≈30 分钟清理）；日志脱敏。
- **只读合规**：不询盘/聊天/收藏/下单/写卖家后台；低频访问，风控升级即冷却停止，不绕过、不破解。
- **账号**：登录可选，用本人/授权买家账号；不共享账号与 profile；不将采集数据用于协议/法律不允许的用途。
