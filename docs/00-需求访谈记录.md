## 0. 背景与目标

- 目标：把 **阿里国际站 alibaba.com** 的**一小块能力**封装成本机常驻、只读、带缓存的客户端，复用 `~/cloak-env` 的 cloakbrowser 运行环境（独立 profile），对外提供 **CLI / REST / MCP / SKILL**（与同机 `zhilian-client`、`boss-client`、`tanji-client` 同构）。
- 数据用途：B2B 获客线索——按地区找到中国制造商/工贸企业 → 拿供应商列表 → 看公司详情（入驻年限 / Supplier Index 星级 / 主营产品 / 会员与认证）→ 交给下游 Agent/线索平台/CRM（下游暂不明确，先做通用接口）。
- 明确**不是全量封装**：v1 只覆盖「供应商搜索 + 供应商详情 + 地区字典 + 会员识别」，不做产品/询盘/聊天/收藏等写操作。

用户原始设想（简版）：

```text
┌─ 本机 ────────────────────────────────────────────┐
│  ┌─ ali-client ───────────────────────────────┐   │
│  │  cloak 浏览器常驻会话（独立 profile）        │   │
│  │      ↓ 搜索页 SSR JSON / 详情组件接口        │   │
│  │  SQLite 结构化缓存 + 供应商档案               │   │
│  └────────────────────────────────────────────┘   │
│       ↑↓ search / list / detail / regions         │
│  ┌─ REST / CLI / MCP / SKILL ─────────────────┐   │
│  └────────────────────────────────────────────┘   │
│            ↓  Agent / 线索平台 / CRM              │
└───────────────────────────────────────────────────┘
```

## 3. Round 3（探路实测结论，2026-11-15）

> 完整证据、字段表、截图见 [实测报告](../exploration/2026-11-15/REPORT.md)。

| 主题 | 实测结论（影响设计） |
| --- | --- |
| 搜索数据来源 | 供应商搜索页是 **SSR**，无独立列表 XHR；列表在 `window._PAGE_DATA_.offerResultData.offerList[]`（20/页 + 广告卡），筛选字典在 `snData` |
| 详情数据来源 | 公司页组件接口：**`POST https://<subdomain>.en.alibaba.com/event/app/alisite/render.htm`**，`componentKeys=shopSign,companyCard` 一次拿全 |
| 必备三字段 | `companyJoinYears=6`（入驻年限）、`supplierStars=2`（Supplier Index 星级，0–5，截图 ♥♥）、`supplierMainProducts`/`companyMainMarket`（主要产品）——**全部可结构化拿到** |
| 省市 | `companyRegisterProvince` + `supplierOperationalAddress`（含城市）；**平台没有省/市筛选**（`country` 是唯一地区维度），需客户端补 |
| 会员套餐 | 搜索卡 `isAssessedSupplier` / `verifiedSupplierPro` / `goldYears`；详情 `companyHasPassAssessment` / `companyHasPassOnsite` / `accountIsPaidMember` / `isGold` / `assessmentCertCompany`(SGS) / `identityKey=strengthFactory`；**出口通→金品诚企(Verified Supplier)→领袖卖家(Verified Pro)** 三层可判定 |
| 风控 | headless 连发 2–3 页触发滑块；headful + 10–15s 间隔较稳；**已实现类人拖拽自动过滑块（成功 1 次）**，子域偶发失败需人工兜底 |
| 登录态 | 依赖**会话级 cookie**，浏览器进程一关就掉登录（本机复现 2 次）→ **客户端必须常驻 owner 浏览器进程** |
| 语言 | 中英文同构但值本地化（`6 yrs` vs `6 年`）；已切 English-USD，客户端固定 en-US 归一化 |
| 广告 | 顶展卡 `newAd/adInfo`、`type=freeBlock`；`memberTag`/`type`/`iconList` 不能用来判会员 |

**探路直接结论**：

1. v1 数据链路 = 「搜索页导航 + `_PAGE_DATA_`」+「render.htm POST 详情 + 工厂目录 insights gateway（可选）」。
2. 省市搜索 = **关键词 + 详情回填过滤（推荐 strict 模式）**，另有「地点关键词」快速模式与「认证工厂目录按省浏览」补充（仅省、上限 500）。
3. 会员识别 = 枚举 `verified_pro / verified_supplier / gold_supplier / unknown` + 原始证据字段（详见 [会员套餐规则](../exploration/2026-11-15/membership-plans.md)）。
4. 工程 = 常驻 owner 浏览器（systemd）+ REST 单实例 + 结构化缓存，与 zhilian-client 完全同构。

## 3.5 Round 4（第二轮深挖，2026-11-15 晚）

> 用户追加要求：① 更细致地探索上游接口；② 想办法通过定时弹出的人机核验；③ 判断不登录能否拿到完整信息。
> 证据：`exploration/2026-11-15/artifacts/anon/`（匿名独立 profile）+ `anon-captcha-events.jsonl` + 登录态对照。

| 问题 | 实测结论 |
| --- | --- |
| 不登录能否拿完整信息 | **能**。搜索结果 35 个字段与登录态**完全相同**；详情 `shopSign+companyCard+companyOverview` 全量匿名可拿（含 Supplier Index 星级、年限、主营产品、省市地址、认证与会员标识）；工厂目录匿名可拿。`totalCount` 本身波动（712–784），登录 757 属噪声。 **v1 可 anonymous-first，登录非必需**。 |
| 上游采集链路 | **fetch-first**：① `fetch(搜索 URL)`（same-origin）直接拿 SSR HTML → 解析 `window._PAGE_DATA_`；② 从 www 页 **跨子域 POST** `<sub>.en.alibaba.com/event/app/alisite/render.htm`（CORS 允许），一次拿 `shopSign+companyCard+companyOverview`；③ `insights.alibaba.com` 工厂目录。页面导航只用于兜底/过验证。 |
| 详情接口细节 | `componentKeys` 有效值：`shopSign`、`companyCard`、`companyOverview`、`companyMultimediaSummary`、`globalData`、`productGroups`、`footer`；其余（supplierPerformance 等）返回空，其数据在页面 SSR DOM 里（v1.1 再考虑）。 |
| 接口边界 | 关键词查询可用页 ≈31 页（最后部分页），过滤后更深；`totalCount` 不可靠，应以「返回 0 条」为终止；`pages` 默认 5、硬上限 20。 |
| 过滤参数 | 全部生效且可组合：`assessmentCompany`/`verifiedPro`/`ta`/`reviewScore`/`companyAuthTag`/`productAuthTag`/`tagKvPairIntFilter`/`sortType`；`verifiedPro=1` 样本 `verifiedSupplierPro=true` 3/3。 |
| 人机核验触发 | **仅页面导航触发**（约 8~9 次快速导航/30s）；fetch/XHR（搜索 9 次、详情 30 次、混合 50+ 次）**未触发**。 |
| 过验证方案 | 类人拖拽（缓动+抖动+回拉）+ 失败 reload 重来；3 次触发最终 **3/3 成功**（首次 2/3）；`x5sec` 有效期 **≈30 分钟**；失败/二维码兜底走人工中继。 |
| 异常态 | 人为删 x5sec 后 XHR **挂起不返回**（AbortSignal 也无效）→ 必须 Node 侧 watchdog；导航到搜索页过验证后 fetch 恢复；同 profile 单纯重启浏览器不能恢复（风控绑 cookie/设备）。 |
| 会员判定修正 | `isGold` 不可作出口通判据（非 assessed 付费商家为 false）；`companyHasPassOnsite` ≠ 金品（出口通样本也有）；出口通 = `accountIsPaidMember=true` 且 `companyHasPassAssessment=false`；Verified Pro 样本 3/3 同时 assessed。 |
| 新增可用字段 | `companyOverview`：成立年份、年营收（数字或区间文案）、员工数、主要市场、付款/交货条款、合同制造、公司简介、能力标签等。 |

## 4. 设计决策（第二轮深挖后更新）

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 项目命名 | `ali-client`；CLI `ali`；MCP 前缀 `ali_`；MCP server `ali-client` | 与 boss/zhilian/tanji 命名一致 |
| REST 端口 | `127.0.0.1:8792` | 8787/8790/8791 已被占用 |
| 数据目录 | `~/.ali-client`（profile / cache / logs / run） | 与其他 client 隔离 |
| 环境变量前缀 | `ALI_` | 与 `BOSS_`/`ZHILIAN_` 对齐 |
| systemd | `ali-client.service` | 同构 |
| **登录定位** | **anonymous-first**：v1 默认匿名（搜索/详情/工厂全部可用）；登录可选（人工一次，会话级） | 第二轮实测匿名字段完整；登录只影响买家侧功能 |
| 浏览器 | 常驻单实例、headful、独立 profile；**只保留 1 个 www worker 页** | 登录态是会话级；headful 风控更低；worker 页承载全部 fetch |
| **采集策略** | **fetch-first**：① worker 页内 `fetch(搜索 URL)` → 解析 `_PAGE_DATA_`；② 跨子域 CORS `POST render.htm`（`shopSign,companyCard,companyOverview`）；③ `insights` 工厂目录；④ 页面导航仅用于兜底/过验证 | 实测 fetch 150+ 次无滑块；详情 30/30 成功 41s；不导航即不触发验证 |
| 语言/币种 | 固定 `en-US` + `USD`（首次初始化切换一次） | 字段值稳定 |
| 搜索 | fetch 20 条/页；按 companyId 去重；广告卡标记；`pages` 默认 5、硬上限 20；以「返回 0 条」为终止（`totalCount` 不可靠） | 分页边界实测 |
| 详情 | render.htm（3 组件），7 天缓存；并发 ≤2、间隔 ≥0.6–1s | 一次拿全、可缓存 |
| 省市 | `province`/`city` 参数 + `locationMode=strict|keyword|off`；strict 默认（详情回填过滤，单查询 enrich ≤60），keyword 快速模式 | 平台无省市筛选；详情回填实测 0.3–0.8s/家 |
| 地区字典 | 静态 JSON：内地 31 省 + 地级市（中文/英文/拼音/别名/Ali 拼写归一） | 用户要求省市两级 |
| 会员 | 枚举 + 证据；**修正**：`isGold` 不作出口通判据；`companyHasPassOnsite` ≠ 金品；出口通 = `accountIsPaidMember=true` 且 `assessment=false`；Supplier Index = `supplierStars`（≠ reviewScore） | 第二轮样本证据 |
| 缓存 TTL | 搜索 query 2h / 供应商详情 7d / 工厂目录 24h / 地区字典 365d | 沿用 boss/zhilian 默认 |
| 限频 | 页面导航 ≥10s；fetch 搜索 0.8–1.2s/次；详情并发 2、0.6–1s/次；单查询 enrich ≤60；全部可配 | 实测无滑块区间 |
| **验证治理** | 自动拖拽（缓动+抖动+回拉，失败 reload 重试 ≤3）→ 失败转人工/REST 中继；`x5sec` ≈30min；**fetch/watchdog 15–20s 超时**，超时走「导航该 URL → 过验证 → 重试 fetch」；连续 2 次失败进冷却 | 第二轮实测 3/3 最终成功；挂起异常可恢复 |
| 只读 | 不询盘、不聊天、不收藏、不写后台；只抓公开页面/接口 | 合规与账号安全 |
| 交付 | 文档先行（本记录 + 实测报告 + 接口草案）→ 评审 → 实现 → 实测报告回填 | 用户指定节奏 |

## 6. 与 zhilian-client 的关键差异

| 维度 | zhilian-client | ali-client |
|---|---|---|
| 登录 | 智联扫码/短信 | 国际站账号密码/手机号（买家账号）；无扫码入口 |
| 数据来源 | SSR `__INITIAL_STATE__` + fe-api | SSR `window._PAGE_DATA_` + alisite render.htm 组件接口 |
| 地区 | 城市码 `jl`（官方筛选） | **无官方省/市筛选**（只有 `country`）→ 客户端回填过滤 |
| ID | positionNumber / companyNumber | `companyId`（数字）+ 供应商子域 |
| 列表字段 | 职位/公司 | 供应商卡片（年限/评分/认证/产品） |
| 会员体系 | 无 | **出口通/金品诚企/领袖卖家** 识别（本项目重点） |
| 风控 | 腾讯 EdgeOne | 阿里滑块 `nc_1` + 子域风控 |
| 登录持久性 | token 可持久化（≈7/30 天） | **会话级，浏览器进程关闭即掉** |
